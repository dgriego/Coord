# 0.1: Fresh repo and tooling

> Status: **Built** (2026-11-02). GitHub CI green: run 41587967295
> Money gate: no · Native app: no

## Why

Every later slice lands in this repo. If the rules (strict types, lint, boundaries, coverage, CI) are in place before the first line of product code, bloat and pattern drift get caught by a machine instead of in review. This slice ships **no product code**, only the empty house with the rules built in.

## In scope

1. **Archive the old app.**
   - Tag the current `main` commit (`8c49ac3`) as `legacy-m2` so nothing is lost.
   - Delete `apps/`, `packages/`, `scripts/`, `vercel.json`, `.claude/launch.json` and the old `docs/*.html` on this branch.
   - Keep `PLAN.md`. Rewrite `README.md` for the new layout.
2. **Workspace.**
   - Root `package.json` with npm workspaces (`packages/*`, `apps/*`), Node 24 LTS (`engines` plus `.nvmrc`) and exact pinned versions.
   - `tsconfig.base.json` with `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `verbatimModuleSyntax`.
3. **Code quality.**
   - ESLint (flat config) with typescript-eslint's type-aware rules and Prettier. The rules that keep code readable:
     - no `any`;
     - no floating promises;
     - max function length 40 lines;
     - max file length 250 lines;
     - consistent type imports.
   - Floating-point math on money will be caught by the money kernel's types in 0.2, not by lint.
4. **Boundaries.** A `dependency-cruiser` config with the rules from the plan, written now so they apply the moment those packages exist:
   - `money` imports nothing;
   - `domain` imports only `money`;
   - `ui-*` never imports `api` or `data`;
   - apps never import each other;
   - no circular imports.
5. **Tests.** Vitest workspace config with v8 coverage. Thresholds are set per package: 100% branches for `money` and `domain`, 90% elsewhere.
6. **One command.** `npm run ci` runs typecheck, lint, boundaries, tests with coverage, and format check. The same steps run in GitHub Actions on every push and PR.
7. **Dependency updates.** Renovate config: exact pins, grouped weekly PRs, and CI must pass to merge.
8. **Docs skeleton.**
   - `docs/patterns.md`: the registry; entries are filled in as each pattern lands.
   - `docs/dependencies.md`: with entries for every tool below.
   - `docs/adr/000-template.md`.
   - `docs/adr/001-typescript-6.md`.
   - `docs/features/_template.md`: the brief template, already written.

## Decision for you: TypeScript 6.0.3, not 7

TypeScript 7 (the new native compiler) is the latest release. But **typescript-eslint, the standard TS linter, only supports TypeScript below 6.1**. The old repo used TS 7 and had no linting, probably for that reason.

I recommend pinning **TypeScript 6.0.3**:

- It is Microsoft's final release of the JavaScript-based compiler.
- The whole ecosystem supports it: lint, Expo, Vite, Storybook.

We move to 7 when typescript-eslint supports it, and Renovate will tell us when. The cost is slower type checks, which won't matter at our size for a long while.
